# SHINE SKIN 디자인 명세서

작성일 2026년 10월 16일 · 최종 변경 2026년 10월 18일 · 버전 1.9 · 전체 문구·배치 정리와 최종 검수 반영

**펄 라이트 글래스와 풍부한 애니메이션**을 제품 탐색·비교·구매 준비 전반에 적용한다. 밀크 화이트와 아이스 블루, 배경이 비치는 유리, 진주빛 반사, 큰 제품 연출이 공통 언어다. 사용자는 마감일보다 완성도를 우선하며 세부 UI까지 정교하게 만들기를 요청했다.

[PRD](SHINE_SKIN_PRD.md)의 R01–R14를 어떤 모습과 동작으로 구현할지 정한다. 화면 P01–P09의 배치는 [와이어프레임](SHINE_SKIN_WIREFRAMES.html)에서 확인한다. 아래 픽셀·색상·문구·구성 세부값은 **인터뷰를 바탕으로 디자이너가 제안한 초안**이며, 사용자 시안 검토 후 조정한다.

## 1. 최종 방향과 표현 원칙

### 1.1 방향

- 맑고 촉촉한 인상, 일상에서 접근할 수 있는 정교함.
- 화려함의 중심은 빛·재질·깊이·움직임이다. 채도가 강한 네온과 유아적인 캐릭터 장식은 피한다.
- 브랜드 소개의 긴 이야기는 P09에 둔다. 홈은 제품과 비주얼 브랜딩 중심이다.
- 제품·제형 사진이 주도하고 글자는 선택을 돕는다. 유리 조형은 제품을 가리거나 읽기를 방해하지 않게 구성한다.
- 제품을 비교하는 고객에게 가격·용량·사용감·피부 타입·상황이 빠르게 보여야 한다.
- 고객에게는 친근한 존댓말, 상품 속성에는 짧고 정확한 설명을 사용한다. 임상·치료·연구 기관을 연상시키는 근거 없는 권위 표현은 쓰지 않는다.

### 1.2 레퍼런스에서 반영할 원칙

| 자료 | 반영 원칙 | SHINE SKIN에서 바꿀 부분 |
|---|---|---|
| 첨부 이미지 3 | 밝은 아이스 블루, 얇고 밝은 유리 경계, 배경이 비치는 깊이. | 흰 글자 대신 짙은 본문색 사용. 꽃은 보조 재료이며 제품이 주인공. |
| 첨부 이미지 2 | 유리 내부에 비치는 배경, 곡면의 굴절과 반사, 둥근 조작 요소. | 음악 플레이어 형태·콘텐츠를 가져오지 않음. 바다 전체를 그대로 배경으로 고정하지 않음. |
| 첨부 이미지 1 | 입체 유리와 배경의 앞뒤 관계, 가장자리 하이라이트. | 어두운 식물 배경·주황 중심 팔레트는 선택하지 않음. |
| HERA·LANEIGE 공식 상품 분류 | 유형별 탐색, 스킨케어와 메이크업 구분, 고민·제품 속성 안내. | 화면·사진·고유 문구를 복제하지 않음. 업계 인기 순위나 판매 실적의 근거로 쓰지 않음. |

첨부는 정지 이미지다. 아래 모션은 별도 설계 제안이며 참고 이미지의 실제 애니메이션을 확인했다는 의미가 아니다.

## 2. 공통 디자인 토큰

디자인 토큰은 여러 화면에서 반복해서 사용하는 공통 값이다. 예를 들어 ‘주요 버튼 색’을 한 값으로 정하면 상품 상세와 주문 화면의 버튼이 같은 기준을 유지한다.

### 2.1 색상

| 토큰 | 제안 값 | 역할 |
|---|---|---|
| `color.bg` | `#F4FAFC` | 전체 바탕, 넓은 휴식 영역 |
| `color.surface` | `#FFFFFF` | 읽기·입력·주문 요약 면 |
| `color.ice` | `#D9EFF5` | 히어로 깊이, 추천 영역의 옅은 바탕 |
| `color.pearl` | `#E9EDF3` | 진주빛 보조 색면 |
| `color.silver` | `#CAD9E0` | 장식 경계·분리선. 입력칸 식별용으로 단독 사용하지 않음 |
| `color.ink` | `#17313A` | 제목·본문·주요 정보 |
| `color.muted` | `#526976` | 보조 설명·레이블 |
| `color.primary` | `#1E5969` | 주요 CTA와 선택 상태 |
| `color.primary-hover` | `#174957` | 주요 버튼 호버·누름 |
| `color.accent` | `#9CD9EA` | 빛·면 강조. 흰 배경 위 작은 글자로 쓰지 않음 |
| `color.field-border` | `#718C99` | 필드·선택 컨트롤의 식별 경계 |
| `color.focus` | `#226B81` | 키보드 포커스 |
| `color.success` | `#23724A` | 로컬 장바구니 등 완료 피드백 |
| `color.error` | `#B33149` | 입력 오류와 설명 |
| `color.warning` | `#795400` | 비교 개수 제한 등 주의 안내 |
| `color.disabled-bg` | `#DEE7EB` | 비활성 면 |
| `color.disabled-text` | `#6F7B80` | 비활성 문구 |

성공·오류는 색만으로 구분하지 않고 문장과 아이콘을 함께 사용한다. 본문 4.5:1, 큰 글자 3:1 이상을 검수 목표로 삼는다. 반투명 면은 합성된 실제 배경과 움직이는 장면에서 따로 측정한다. 토큰의 단색 대비만으로 유리 위 가독성을 통과 처리하지 않는다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 2.2 유리 재질

| 토큰 | 제안 값 | 적용 위치 |
|---|---|---|
| `glass.art-fill` | 흰색 18–30% | 히어로 장식 조형. 필수 정보 올리지 않음 |
| `glass.nav-fill` | 흰색 72% | 밝은 바탕의 헤더·메뉴 |
| `glass.read-fill` | 흰색 88% | 텍스트가 많은 패널·필터 |
| `glass.blur` | 20px, 작은 화면 12px | 정적인 헤더·패널. 큰 영역 전체의 블러를 연속 애니메이션하지 않음 |
| `glass.saturation` | 108% | 색 왜곡을 줄인 은은한 유리 |
| `glass.edge` | 흰색 70%의 1px 선 + 바깥쪽 옅은 청회색 선 | 밝은 배경에서도 두께감 구분 |
| `shadow.float` | `0 16px 48px rgba(30, 74, 88, .10)` | 헤더·떠 있는 패널 |
| `shadow.dialog` | `0 24px 80px rgba(23, 49, 58, .18)` | 대화상자·드로어 |

글자가 배경에 묻히면 읽기 면의 불투명도를 올리거나 제품 뒤 배경을 정리한다. 배경 흐림 미지원 환경에서는 읽기 면을 불투명 흰색으로 대체하고 테두리·반사광으로 재질의 인상을 유지한다. 실제 굴절은 히어로의 시각 연출에서 구현 여부를 검증하며 CSS 블러를 물리적 굴절이라고 설명하지 않는다.

### 2.3 글꼴과 글자 체계

확인한 로컬 후보는 Pretendard, 에스코어 드림, 카페24 계열 등이다. **본문·조작 요소는 Pretendard, 큰 제목은 에스코어 드림**을 우선 제안한다. 두 계열 안에서 역할을 유지하고 세 번째 장식 글꼴을 무분별하게 더하지 않는다.

| 역할 | 데스크톱 | 모바일 | 굵기·간격 |
|---|---|---|---|
| 히어로 제목 | 64–80px | 40–48px | 에스코어 드림 3 Light, 줄높이 1.15, 한글 자간 기본 |
| 페이지 제목 | 48px | 32px | 에스코어 드림 4 Regular, 줄높이 1.25 |
| 섹션 제목 | 40px | 28px | 에스코어 드림 4 Regular, 줄높이 1.3 |
| 상품명·소제목 | 20px | 18px | Pretendard 500, 줄높이 1.4 |
| 본문·레이블·버튼 | 16px | 16px | Pretendard 400–600, 기본 줄높이 1.45 |
| 보조 문구 | 14px | 14px | Pretendard 400, 줄높이 1.45 |
| 가격·비교 수치 | 18–24px | 16–20px | Pretendard 500, 숫자 폭 고정 기능 적용 |

긴 한글 설명은 실제 문구로 읽기 검토 후 필요하면 줄높이 1.55까지 보정한다. 정보 본문은 대략 한 줄 24–38개 한글 글자 범위에서 읽기 편한 폭을 잡고 640px 이상 길게 늘이지 않는다. 제목은 단어 단위 줄바꿈을 우선하되 320px에서 넘치지 않도록 예외 줄바꿈을 허용한다. 브랜드 영문 대문자는 0.06em 자간을 적용한다. 전체 본문에 넓은 영문 자간을 적용하지 않는다.

Pretendard는 [공식 SIL OFL 라이선스](https://raw.githubusercontent.com/orioncactus/pretendard/main/LICENSE)를 보존한다. 에스코어 드림은 [공식 사용·재배포 조건](https://s-core.co.kr/company/font/)을 따른다. 에스코어 원본 파일의 수정·서브셋·변환을 당연히 허용한다고 보지 않는다. 폰트 전체 굵기를 한꺼번에 로드하지 않으며 필요한 원본·공식 웹 배포본을 확인한 뒤 적용한다. 최종 조합과 로고 글자 보정은 대표 시안에서 확정한다.

### 2.4 여백·그리드·형태

| 항목 | 데스크톱 ≥1024px | 태블릿 640–1023px | 모바일 <640px |
|---|---|---|---|
| 콘텐츠 최대 폭 | 1280px | 화면에 맞춤 | 화면에 맞춤 |
| 양옆 여백 | 40–64px | 32px | 20px, 320px에서는 16px |
| 기준 그리드 | 12열, 열 간격 24px | 8열, 24px | 4열, 16px |
| 홈 상품 목록 | 3열 | 2열 | 2열 |
| 상품 목록 P02 | 248px 필터 + 3열 상품 | 필터 패널 + 2열 | 필터 패널 + 2열 |
| 상세·주문 | 주 내용과 요약 2영역 | 긴 정보 순서대로 적층 | 1열, 주요 CTA 하단 고정 |
| 큰 섹션 간격 | 128px | 96px | 72px |
| 관련 콘텐츠 간격 | 32–48px | 24–32px | 20–24px |
| 상품 카드 내부 | 16–20px | 16px | 12–16px |

공통 여백 단계는 4·8·12·16·20·24·32·40·48·64·80·96·128px이다. 제목과 해당 설명은 가깝게, 다음 주제와는 멀게 둔다. 글자·버튼·이미지의 시작선을 같은 그리드에 맞춘다.

모서리는 버튼 16px, 필드 12px, 카드 24px, 패널 28px, 큰 유리 조형 40px 이상을 출발점으로 삼는다. 내부 요소가 겹쳐 들어갈 때 바깥 반경에서 안쪽 간격을 뺀 반경을 사용한다. 예: 패널 28px 안쪽 간격 12px이면 안쪽 면은 16px.

## 3. 헤더와 홈의 섹션 설계

모든 홈 구간은 P01이며 R01·R02·R03·R12·R14에 연결된다. CTA는 클릭 후 이동을 유도하는 주요 버튼이다. 예를 들어 ‘내 루틴 찾기’는 홈의 추천 영역으로 이동한다.

| 구간 | 목적·핵심 메시지·문구 방향 | 자료·배치·우선순위 | 버튼·연결·모바일 |
|---|---|---|---|
| H01 헤더 | 어디서든 탐색·검색·장바구니로 접근. | 글자형 로고, 상품·맞춤 루틴·브랜드 소개 메뉴, 검색, 찜·장바구니·계정. 떠 있는 유리 면. | 로고→P01, 상품→P02, 루틴→H03, 브랜드→P09. 1024px 미만은 메뉴 드로어. |
| H02 히어로 | 제품과 브랜드를 기억시키고 맞는 제품을 찾게 함. 제목안: “피부에 맞추고, 하루에 빛을 더하다.” 본문안: “피부 타입과 오늘의 일정에 맞춰, 나만의 조합을 만나보세요.” | SS02 세럼을 주인공, SS08 쿠션을 보조로 제안. 큰 제품과 유리 곡면이 앞뒤로 겹친 무대. 제목 왼쪽·제품 오른쪽 중심이되 이미지가 그리드를 넘어 확장. | 주 CTA ‘내 루틴 찾기’→H03, 보조 ‘제품 둘러보기’→P02. 모바일은 제목·CTA 뒤 제품 무대, 주인공이 중앙에 남도록 전용 크롭. |
| H03 제품 찾기 | “나의 피부, 오늘의 루틴.” 선택의 이유가 보이는 추천. | 1단계 피부 타입, 2단계 상황, 3단계 제품 조합. 큰 하나의 유리 패널 안에서 단계 변화. 추천 제품과 이유가 정보 우선. | 건너뛰기·초기화·상세 보기·옵션 선택 후 담기. 모바일은 단계별 적층, 선택 상태 유지, 다음 단계로 부드럽게 스크롤. |
| H04 컬렉션 | “당신의 빛을 고르는 시간.” 추천 외 상품도 비교. | 분류 탭과 6개 내외 상품 목록. 이미지→상품명→가격→태그→찜·비교 순. 반복되는 격자는 실제 상품 비교가 목적이므로 사용. | ‘전체 상품 보기’→P02, 상품→P03, 비교→P04. 모바일 2열, 가격과 조작 영역 잘림 방지. |
| H05 제형·마무리 | “가볍게, 촉촉하게. 원하는 마무리로.” 온라인에서 질감 판단을 도움. | 제형 확대 이미지와 제품의 피부 표현 이미지를 크게 교차 배치. 임상 전후 사진을 사용하지 않음. 긴 카드열 대신 큰 사진+짧은 설명. | 제형별 제품 보기→P02의 해당 속성 필터. 모바일은 이미지→설명→연결 순, 본문을 사진 위에 겹치지 않음. |
| H06 비주얼 브랜딩 | 짧은 메시지로 인상을 남김. 문구안: “피부의 취향, 하루의 리듬.” | 큰 글자·패키지 디테일·얇은 유리 리본. 긴 브랜드 이야기나 연혁 없음. 앞선 제품 격자와 다른 밀도로 리듬 전환. | 작은 ‘SHINE SKIN 알아보기’→P09. 모바일은 제품 디테일과 2줄 문구. |
| H07 선택 도움말 | 추천·비교 이용에 남은 질문 해결. | ‘피부 타입을 모르겠다면?’, ‘제품을 비교하려면?’, ‘상황을 바꿀 수 있나요?’ 3개 안팎의 펼침 목록. | 제목 버튼으로 열고 닫기. 키보드·터치 동일. 배송·환불 등의 미정 운영 정책을 답변으로 만들지 않음. |

### 히어로 상세 제안

- 데스크톱: 최소 높이 700px, 화면 높이에 따라 약 92svh에서 최대 960px 범위. 내용이 넘치면 높이를 늘린다. 짧은 노트북 화면에서 CTA가 밀리지 않도록 제목과 이미지 크기를 함께 조정한다.

- 유리의 큰 곡면이 제품 뒤에서 앞으로 이어지고, 가장자리의 빛이 시선을 H03으로 유도한다. 전체를 하나의 둥근 카드에 가두지 않는다.

## 4. 나머지 화면 명세

### P02 상품 목록과 검색 · R03·R05·R06

제목·검색어·결과 수 → 분류별 하위 메뉴 → 필터·정렬 → 상품 목록 → 페이지 이동 순으로 배치한다. 데스크톱은 왼쪽 필터, 오른쪽 3열 목록이다. 모바일은 필터 버튼과 선택 조건 칩을 상단에 두고 2열 목록을 사용한다.

필터는 분류·피부 타입·상황·원하는 마무리로 한정한다. 선택 필터를 개별 제거하거나 전체 해제할 수 있다. 정렬은 추천순·가격 낮은순·가격 높은순·이름순을 제안한다. 판매 실적이 없으므로 판매순·인기순은 쓰지 않는다.

페이지당 6개를 제안한다. 결과가 6개 이하면 페이지네이션을 숨긴다. 페이지·검색·필터를 주소 상태로 유지하고, 필터 변경 시 1페이지로 돌아간다. 결과 없음에는 “조건에 맞는 제품이 없어요”와 조건 해제 버튼을 제공한다.

### P03 상품 상세 · R04·R07

데스크톱은 이미지 약 58%, 정보 약 42%의 두 영역이다. 이미지 확대·썸네일, 상품명·가격·용량·사용감·피부 타입·상황, 색상·수량, 구매 버튼을 우선한다. 아래는 제형, 사용 순서, 추천 조합을 설명한다.

모바일은 경로→갤러리→상품명·가격→핵심 속성→옵션→설명 순이다. 하단 고정 구매 바에서 ‘옵션 선택’을 누르면 선택 패널로 연결한다. 옵션 미선택 상태의 장바구니 동작은 해당 필드로 안내하며 다른 오류를 만들지 않는다.

색상은 색 견본과 이름을 함께 표시한다. 선택 상태는 테두리·체크·이름으로 알린다. 재고나 한정 수량을 창작하지 않는다. 수량은 1–10개를 제안하며 범위 끝의 감소·증가 버튼만 비활성화한다. 제형 사진과 발색은 실제 측정 정보가 아닌 제작 이미지라는 구분을 내부 자료에 유지한다.

### P04 비교함 · R05

상품 머리글과 이미지, 가격·용량·제형·사용감·피부 타입·추천 상황의 행을 정렬한다. 상품별 상세 이동과 제거를 제공한다. 1개뿐이면 ‘비교할 제품 추가’를 보인다. 최대 3개이고 중복 추가는 현재 선택 상태로 알린다.

모바일에서는 화면 전체가 옆으로 넘치지 않게 표 영역 안에서만 가로 이동한다. 항목 열과 제품명 머리글을 유지하고 ‘옆으로 이동해 비교’ 안내를 제공한다. 최대 3개 열 모두를 너무 좁게 압축하지 않는다. 표의 제목·행 머리글·읽는 순서를 보존한다.

### P05 찜과 최근 본 상품 · R06

찜 / 최근 본 상품 두 탭, 개수, 동일한 상품 카드, 비교·상세 이동을 제공한다. 최근 본은 최신 순으로 최대 20개를 제안한다. 빈 탭은 짧은 설명과 ‘제품 둘러보기’ 버튼으로 구성한다. 개별 제거는 즉시 반영하고 되돌리기를 제공한다. 계정이나 장치 간 동기화로 표현하지 않는다.

### P06 장바구니 · R07

데스크톱은 상품 행과 오른쪽 상품금액 요약, 모바일은 세로 상품 행과 하단 주문 CTA다. 행 안의 상품명·옵션·수량·개별 금액을 명확히 구분한다. 체크박스로 주문할 상품을 고를 수 있고 모든 상품이 해제되면 주문 CTA를 비활성화한다.

같은 상품·옵션은 합산하고 다른 옵션은 별도 행으로 둔다. 삭제 후 복원 알림은 6초를 기본으로 하되 키보드 포커스나 마우스가 머물 때 사라지지 않는다. 실제 배송 정책이 미정이므로 무료배송·할인·배송일을 임의로 안내하지 않는다.

### P07 주문과 최종 확인 · R08

진행 표시는 배송 정보 → 결제수단 → 내용 확인의 3단계다. 배송 정보는 수동 입력, 결제수단은 카드 / 간편결제 종류 선택을 제안한다. 카드번호·CVC·인증번호·외부 결제창은 없다. 상품금액 합계와 선택 수단을 확인하고 이전 단계에서 수정할 수 있다.

최종 확인까지는 작동하고 마지막 ‘결제하기’는 비활성이라는 종료 방식을 제안한다. 가짜 주문 번호·접수 완료·결제 중 로딩은 표시하지 않는다. 주요 마지막 버튼의 종료 방식은 문서 검토에서 확인할 항목이다.

### P08 계정과 회원가입 · R09

로그인 / 회원가입을 구분한다. 가입 필드는 이메일·비밀번호·재입력 등을 최소 범위로 제안한다. 문서 검수용 입력 예시는 `shine@example.invalid`처럼 실제 수신자가 없는 값을 사용한다. 이메일 형식 확인을 실제 중복 확인이나 인증 완료로 표시하지 않는다.

레이블은 필드 위에 유지한다. 안내 문구와 오류 문구를 구분한다. 비밀번호 표시 전환은 아이콘 버튼과 ‘비밀번호 표시/숨기기’ 이름으로 제공한다. 필요한 동의 선택은 메모리에서만 체험하고 임의의 약관 전문을 게시하지 않는다. 가입 내용 확인 후 마지막 ‘가입 완료’는 비활성으로 제안한다. 입력된 비밀번호는 확인 화면에서 다시 노출하지 않는다.

### P09 브랜드 소개 · R10

브랜드의 한 문장 → 피부 타입과 일상을 연결하는 관점 → 제품 구성 기준 → 패키지와 재질의 시각 언어 → 상품 탐색 CTA 순이다. 제품·제형 중심의 큰 사진과 짧은 설명을 교차 배치한다. 실제 창립 연도·연구실·제조 공정·수상·설립자 경력을 만들어 넣지 않는다. 모바일은 사진과 설명을 원래 읽는 순서로 쌓는다.

### 5.1 버튼·카드·입력 공통값

- 버튼: 기본 높이 48px, 가로 안쪽 여백 24px, 반경 16px. 아이콘 버튼의 실제 누름 영역은 최소 44×44px를 목표로 한다. 주요 버튼은 짙은 청록 면+흰 글자, 보조 버튼은 읽기 가능한 유리 면+짙은 글자, 텍스트 링크는 짙은 글자와 구분 가능한 반응을 사용한다.
- 카드: 사진 비율과 글자 정렬을 고정하고 필수 속성의 읽는 순서를 유지한다. 모든 섹션을 같은 유리 카드로 감싸지 않는다.
- 입력: 높이 52px, 반경 12px, 필드 배경과 테두리를 부모 면에서 구분한다. 나란한 입력과 버튼은 높이를 같게 맞춘다.
- 포커스: 2px 짙은 포커스 선+3px 간격, 밝고 어두운 배경에서 식별되는 보조 경계. 호버 그림자로 대신하지 않는다.
- 선택: 테두리·체크·텍스트 상태를 함께 변경. 해제할 수 있게 한다.

## 6. 반응형과 고정 요소

브레이크포인트는 배치가 바뀌는 화면 너비 기준이다. 640·1024px는 콘텐츠와 메뉴의 밀도를 고려한 출발점이며, 실제 한글과 이미지로 중간 너비를 확인한 뒤 조정한다.

- 1024px 미만: 전역 메뉴를 드로어로, P02 필터를 시트로 전환. 표·긴 설명은 의미와 순서를 유지한다.
- 640px 미만: 상품 2열·상세와 주문 1열. 히어로 제품은 모바일 전용 크롭, 제목 2–3줄 이내를 목표로 한다.
- 데스크톱 헤더는 상단 16px 여백의 72px 높이, 모바일은 64px 높이를 제안한다. 앵커와 오류 이동에는 헤더보다 큰 96px/80px 스크롤 여유를 둔다.
- P03·P06 모바일 하단 CTA는 안전 영역을 포함해 약 72px+기기 하단 여백을 확보한다. 본문 하단도 같은 크기 이상 비워 마지막 내용이 가려지지 않게 한다.
- 비교 담기 고정 바와 구매 바를 동시에 쌓지 않는다. 주문 화면에서는 비교 바를 숨기고, 시트가 열리면 뒤쪽 고정 바는 조작할 수 없게 한다.
- 입력 키보드가 열리면 필드·오류·현재 단계가 보이도록 하고, 화면에 걸친 구매 바가 입력을 가리지 않게 한다.
- 320px·390px·768px·1024px·1440px와 그 사이 너비, 200% 확대에서 검수한다. 비교표는 이름을 가진 자체 스크롤 영역을 예외로 두되 문서 전체가 옆으로 밀리지 않게 한다. [W3C 리플로 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## 7. 사진·그래픽·로고

- 패키지 제안: 투명·반투명 용기, 펄 화이트 라벨, 얇은 실버 디테일, 짙은 청록 글자. 세럼·크림·쿠션·색조가 같은 브랜드로 보여야 한다.
- 히어로: 큰 제품과 곡면 유리, 얕은 물결·빛의 무늬. 주변 장식보다 제품 실루엣과 로고가 먼저 보이게 한다.
- 상품 썸네일: 4:5 비율, 제품이 프레임 높이의 약 65–78%에 들어오게 통일. 정면 또는 3/4 각도, 바닥과 접지 그림자 유지.
- 상세 갤러리: 1:1 또는 4:5, 용기·패키지·제형·색상 구분. 확대해도 흐리지 않도록 제작 해상도 확인.
- 제형: 큰 접사와 촉감이 느껴지는 표면. 임상 전후·피부 질환·모공 개선을 입증하는 이미지로 제시하지 않음.
- 상황 이미지: 출근·데이트 등 생활 장면은 보조 역할. 히어로를 모델 얼굴 중심으로 바꾸지 않음.
- 글자 위 사진: 밝기 변화가 큰 위치에 본문을 겹치지 않음. 별도 읽기 면과 명확한 대비 확보.
- 아이콘: 한 계열의 선형 아이콘, 20–24px 도형, 실제 누름 영역 44px 이상. 이모지나 문자로 아이콘을 대체하지 않음.
- 로고: SHINE SKIN 글자형, 섬세한 간격과 비례로 정리. 상품 라벨에서도 읽히는 작은 크기 버전 필요.
- 모든 새 이미지의 생성·원본·사용 조건은 내부 자산 기록에 남긴다. 웹에 AI·데모 표기는 넣지 않는다. 대표 시안의 제품·유리 이미지 제작 결과는 11절에 기록했고, 나머지 자산은 후속 제작 범위다.

## 8. 애니메이션 설계

요청한 풍부함은 히어로·섹션 전환·제품 반응이 하나의 리듬으로 이어지도록 만든다. 화면 전체가 동시에 흔들리는 방식으로 구현하지 않는다.

| 대상·목적 | 움직임·시간 제안 | 모바일·대체 표현 |
|---|---|---|
| 히어로 등장 | 제품·글자·유리의 0–120ms 간격 순차 등장, 전체 900ms 안팎. 주요 내용은 처음부터 식별. | 이동 거리 축소, 정보 표시 지연 없음. |
| 유리 굴절과 빛 | 8–12초의 느린 반사광 이동, 제품 앞뒤 깊이 변화. | 핵심 반사광 유지, 동시에 렌더링하는 효과 수 조정. |
| 제품 부유 | 7–10초 주기, 세로 ±10px·회전 ±3도. | 세로 ±6px, 터치와 무관하게 제품 정체성 유지. |
| 스크롤 연결 | 히어로 깊이 최대 40px, H03으로 유리 곡선이 이어짐. 자연 스크롤 유지. | 최대 16px. 반복 고정 스크롤 구간 강제 없음. |
| 추천 선택 | 선택 윤곽 160ms, 결과 교체 220ms 교차 전환. | 레이아웃 높이 변화 완충, 현재 선택과 결과를 읽을 수 있게 유지. |
| 컬렉션·제형 구간 | 사진 등장 400–600ms, 짧은 빛 이동. 콘텐츠 역할에 따라 적용. | 화면 밖 모션 정지, 호버 없이 모든 연결 사용 가능. |
| 호버·누름 | 160ms 빛·색, 100ms 누름, 기울기 최대 3도. | 터치는 짧은 누름·선택 반응으로 대체. |
| 드로어·시트 | 280ms 이동, 배경 밝기 180ms. | 화면 키보드·안전 영역 대응. |
| 모달·토스트 | 180–220ms 불투명도·짧은 이동. | 모션 축소 설정에서는 즉시 또는 120ms 이하 전환. |

기본 완화 곡선은 `cubic-bezier(.22, 1, .36, 1)`을 제안한다. 탄성이 큰 과장된 튕김은 기본 동작에 사용하지 않는다.

기기의 ‘움직임 줄이기’를 자동 반영하고 히어로·푸터의 설정으로도 조절한다. 줄이기 상태에서는 반복 부유·패럴랙스·연속 굴절을 정지하고 정적인 제품·반사광 조합을 유지한다. 5초 이상 지속되는 자동 움직임은 사용자가 정지할 수 있게 설계한다. [W3C 정지·숨김 설명](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)

## 9. 성능과 품질 검수

- 첫 화면은 정적인 제품 기본 이미지와 읽을 수 있는 콘텐츠를 먼저 보여주고, 무거운 효과는 준비 후 시작한다.
- 이미지 크기와 비율을 미리 예약해 늦게 도착해도 화면이 밀리지 않게 한다. 아래쪽 이미지는 지연 로딩한다.
- 애니메이션은 가능한 변형·불투명도 중심으로 처리한다. 매 프레임 큰 배경 블러·레이아웃 크기·그림자를 다시 계산하지 않는다.
- 동시에 실행하는 무거운 효과를 제한하고 화면 밖·비활성 탭에서는 정지한다. 저성능 환경에서는 정적인 유리 이미지와 가벼운 빛 이동으로 대체한다.
- **제안 목표:** 대표 환경에서 LCP 2.5초 이하, CLS 0.1 이하, 일반 조작 반응 200ms 이내. 실제 성능을 측정하지 않았으며 사용 기기·환경을 정해 결과와 함께 보고한다.
- 큰 제품 이미지·폰트·영상의 실제 파일 용량을 확인한다. 폰트 전체 굵기·고해상도 영상의 무조건 선로딩을 피한다.
- 실제 사이트 검수는 PRD AC01–AC18을 따른다. 현재 문서와 와이어프레임이 사이트의 접근성·성능 통과를 증명하지 않는다.

## 10. 문서 검토에서 확인할 제안

12종 상품안과 개별 가격, 피부 타입·상황의 세부 분류, 히어로의 세럼+쿠션 조합, 문구와 글꼴 조합, 토큰 수치, 마지막 결제·가입 버튼 비활성 종료는 설계 제안이다. 사용자가 문서 기준의 대표 시안 제작을 승인했다. 아래는 구현 화면의 기준이며, 최종 시각 방향의 승인은 실제 화면 검토 후 기록한다.

## 11. 대표 시안 구현 기록 — H01·H02·H03

[화면 비교](SHINE_SKIN_PREVIEW.html)와 [실제 홈 화면](shine-skin/index.html)을 함께 제공한다. 홈의 나머지 섹션과 독립 상세·비교·가입·주문 페이지는 이번 시안의 범위가 아니다.

### 11.1 시안에 적용한 값과 배치

| 요소 | 실제 적용 | 초안에서 조정한 이유 |
|---|---|---|
| 헤더 | 데스크톱 높이 76px·상단 20px·좌우 32px, 1024px 미만 68px, 모바일 62px·상단 12px | 로고·탐색·검색·찜·장바구니를 하나의 떠 있는 유리 면으로 묶음. 작은 화면에서는 찜을 메뉴 안에 둠. |
| 제목 | 넓은 화면 `clamp(48px, 4.55vw, 68px)`, 1024–1199px 50px, 모바일 `clamp(32px, 9.7vw, 48px)` | 실제 한글 제목을 2줄로 유지. 320px에서 32px로 줄여 잘림 방지. |

헤더의 상품·브랜드 메뉴는 이번 시안에서 연결 패널을 연다. 브랜드 패널에는 승인된 짧은 소개만 담으며, 계획된 긴 소개 페이지를 대체하지 않는다. 계정·비교·최근 본 상품·결제·가입 흐름은 후속 범위다.

### 11.2 글꼴과 자산

- 제목·로고는 로컬 S-Core Dream 3·4의 원본 OTF를 사용했다.
- 본문은 Pretendard Regular·Medium. 로컬 TTF가 Chromium의 글꼴 검사에서 거부되어 같은 제작자의 공식 WOFF2를 프로젝트 안에 저장해 사용했다. 실행 중 외부 글꼴 서버에 접속하지 않는다.
- 히어로는 세럼·쿠션·유리 리본의 투명 이미지다. 추천 제품은 6종 팩샷으로 제작했다. 12종 전체 패키지는 후속 제작 범위다.
- 두 이미지는 원본 크기와 투명도를 유지한 WebP로 최적화했다. 약 349KB·177KB이며, 생성 프롬프트·원본·사용 범위는 `shine-skin/ASSET_MANIFEST.json` 및 이미지 옆 기록에 남겼다.
- 가상 상품과 가격의 기획용 성격은 내부 문서에서 유지한다. 웹 화면에는 임시·AI·데모 표기를 넣지 않는다.

### 11.3 모션과 동작

- 제품은 데스크톱에서 8초 주기로 세로 15px 범위·회전 약 0.7도로 부유하고, 모바일은 세로 7px로 줄인다.
- 빛의 사선 흐름은 12초, 독립 물방울은 10초 주기로 움직인다. WebGL은 약 30fps 간격으로 빛 무늬를 갱신한다. **유리 리본의 굴절은 이미지 재질 표현이며, WebGL이 실시간 제품 굴절을 계산하는 것은 아니다.**
- 마우스에 따라 제품 무대의 위치를 최대 약 6px·4.5px 움직이고 약하게 기울인다. 모바일에서는 포인터 효과를 적용하지 않는다.
- 제품 정보 캡션과 주요 버튼은 누르기 쉽도록 고정한다. 추천 카드 결과는 300ms·45ms 간격으로 바뀌며, 팝업은 300ms로 열린다.

### 12.1 보이는 배경과 입체 면

- 입체감은 촬영·생성 이미지의 깊이, 영상의 액체 움직임, 화면의 원근 배치와 유리 가장자리 표현의 조합이다. 자유롭게 회전하는 전체 3D 쇼핑 공간을 구현한 것은 아니다.

### 15.1 상단과 제품 종류

헤더 순서: **전체 제품 → 스킨케어 → 메이크업 → 선케어 → 나만의 루틴 → 브랜드**. 제품군과 피부/상황 기준을 섞지 않는다. 메가메뉴는 여러 하위 종류를 한 번에 펼치는 넓은 메뉴다. 예를 들어 메이크업을 열면 베이스·립·아이/치크에서 파운데이션이나 립스틱으로 바로 이동한다.

| 대상 | 배치와 실제 값 | 동작 |
|---|---|---|
| 데스크톱 헤더 | 1200px 이상에서 6개 메뉴, 메뉴 간격 24px·글자 14px | 제품군 클릭·Enter 또는 마우스 진입으로 열기. 한 번에 한 개. 바깥 클릭·Escape·경로 이동·작은 화면 전환으로 닫기 |
| 스킨케어·메이크업 펼침 | 헤더 너비, 위 간격 12px. 소개 180px / 종류 영역 가변 / 대표 제품 190px, 간격·안쪽 32px | 실제 하위 종류·제품 수와 대표 제품 상세로 연결. 포커스가 패널 안에 있으면 유지하고 Escape 후 해당 제목에 복귀 |
| 선케어 펼침 | 오른쪽 정렬, 최대 880px. 소개 160px / 종류 가변 / 대표 제품 190px | 종류가 3개이므로 짧고 밀도에 맞는 패널 |
| 유리 재질 | 배경 #E3F5FDE6, 흐림 24px·채도 120%, 흰 경계, 모서리 30px, 아래로 떨어지는 부드러운 그림자 | 승인된 푸른 배경·반사와 연결하되 종류 글자의 대비 유지. 높이는 화면 높이−130px 이내, 필요시 패널 내부 스크롤 |
| 모바일 메뉴 | 1199px 이하 햄버거 버튼 → 기존 드로어. 전체 제품 24, 세 제품군과 개수, 루틴·브랜드, 보조 링크 순 | 제품군은 아코디언, 즉 제목을 눌러 내부 목록을 펼치는 방식. 유형은 2열. 선택 후 드로어 닫기, 같은 경로를 다시 골라도 닫기 |
| 메뉴 등장 | 220ms, 기존 ease 사용 | 움직임 줄이기 설정에서는 등장 애니메이션 없음. 모바일에서 호버 필요 없음 |

하위 유형은 `PRODUCT_KINDS`의 한 데이터에서 생성한다. 스킨케어는 세안·첫 단계 / 데일리 케어 / 스페셜 케어, 메이크업은 베이스 / 립 / 아이·치크로 묶는다. 선케어는 선크림·톤업 선케어·선스틱이다. 총 19개 유형 모두 실제 제품이 있다.

### 15.2 목록과 새 패키지

- P02는 전체 24종·페이지당 12개. 1400px 이상 4열, 중간 화면 3열, 639px 이하 2열. 4열 카드 사진 높이 236px·팩샷 폭 130px·본문 좌우 16px·상품명 16px. 기존 상세·찜·추천의 열 수는 임의로 늘리지 않는다.
- 제품군 칩 아래에는 유형별 보조 메뉴를 둔다. 높이 최소 44px·가로 간격 24px, 모바일 글자 13px·간격 22px. 현재 유형은 색·밑줄·`aria-current`를 함께 사용한다. 작은 화면에서는 이 줄 안에서만 가로 이동한다.
- 검색·피부·상황·정렬을 바꾸면 제품군/유형 링크도 최신 조건으로 갱신한다. 제품군을 바꾸면 이전 유형과 페이지를 해제한다. 검색·피부·상황 조건으로 결과가 없으면 초기화 가능한 기존 빈 결과 화면을 쓴다.
- 추가 12종은 6개 제품을 담은 투명 팩샷 이미지 2장으로 구성한다. 각 이미지 1254×1254px, 약 208KB·144KB. 기존 패키지의 실버 캡·차가운 블루·따뜻한 립 색상과 연결한다. 클렌징 밤은 가로로 넓은 용기를 담도록 배경 위치 2%, 미스트는 이웃 용기가 비치지 않도록 52%로 조정했다.
- 상품명·제안 가격·실제 옵션을 먼저 읽고 찜·비교·담기로 이어진다. 모바일의 투명 클릭 영역 44×44px와 기존 색상 미선택 오류 안내를 유지한다.

버튼·입력·오류·포커스·모션 축소는 14절의 공통 규칙을 상속한다. 새 세계·전역 토큰 교체가 아니므로 DESIGN.md와 토큰 sidecar를 보존한다. 실제 검수와 미확인 환경은 [24종 검수 기록](SHINE_SKIN_CATALOGUE24_QA.md)에 기록한다.

## 16. 첫 화면을 채우는 히어로 높이

2026-10-18 사용자가 스크롤 전에는 히어로만 꽉 차게 보이도록 요청했다. 기존 최대 960px 제한을 제거하고, 히어로의 최소 높이를 현재 브라우저 표시 영역 전체인 `100dvh`로 설정했다. 이를 지원하지 않는 브라우저에는 `100vh`를 사용한다. 이 값은 13절의 높이 범위보다 우선한다.

데스크톱의 내부 배치도 같은 최소 높이를 사용해 기존 제목과 제품을 세로 가운데에 둔다. 640–1023px와 모바일의 내부 세로 배치는 콘텐츠의 자연 높이를 유지하고 바깥 히어로가 최소 화면 높이를 채운다. 작은 화면·확대 상태에서 내용이 화면보다 길어지면 섹션을 늘리며 고정 높이로 글자나 버튼을 잘라내지 않는다. 제목·제품 크기·문구·유리·영상·버튼과 다음 섹션의 내용은 유지한다. 스크롤 또는 ‘내 루틴 찾기’로 추천 영역에 진입한다.

정적 미리보기에 남은 이전 스타일을 피하도록 `glass-v2.css?v=6`으로 연결했다. 화면 크기별 실제 확인과 실기기 미확인 범위는 [히어로 높이 검수](SHINE_SKIN_HERO_VIEWPORT_QA.md)에 기록한다.

본문 바로가기는 주소를 바꾸지 않고 현재 보이는 main에 포커스와 스크롤을 옮긴다. 다음 Tab은 해당 본문의 첫 조작 요소로 이어지며 검색 조건·상품 옵션·주문 입력을 보존한다. 모바일 상세의 하단 ‘제품금액’은 단가가 아닌 선택 수량을 곱한 합계이며 본문 금액과 함께 갱신한다.

모바일 목록·찜·관련 상품의 하트와 빠른 옵션은 보이는 36px 채움/기존 아이콘을 유지하되 가운데 정렬한 투명 조작 영역을 44×44px로 확보한다. 374px 이하의 빠른 옵션도 실제 조작 영역은 44px이며 옆의 비교 조작과 겹치거나 카드에서 잘리지 않아야 한다.


## 17. 브랜드 이야기의 홈 통합

2026-10-18 사용자 요청으로 짧은 유리 배너와 독립 소개 페이지를 제거하고 기존 전체 콘텐츠를 홈 #brand에 통합했다. 제품·제형 소개 다음, 도움말 이전이다. 과거 별도 페이지 계획보다 이 절이 우선한다. 기존 두 이미지·본문·세 기준·루틴/제품 CTA를 보존하고 새 주장·자산을 만들지 않는다.

도입은 글 왼쪽/제품 이미지 오른쪽, 다음 설명은 이미지 왼쪽/글 오른쪽, 그 아래 세 기준과 중앙 CTA로 이어진다. 홈의 브랜드 제목은 h2, 아래 다섯 제목은 h3로 바꿨으며 해당 CSS도 같이 옮겨 기존 S-Core Dream·Pretendard 크기·줄 간격을 보존했다. 경로 표시와 상세 페이지 전용 상단 여백은 옮기지 않는다.

- 공통 최대 폭1280px 컨테이너, 바깥 상하112px·639px 이하68px, 기존 푸른 소개 배경을 사용한다.
- 768px 이상 도입 .9fr/1.1fr·간격60px, 설명1fr/1fr·간격80px, 세 기준3열. 1023px 이하 두 설명 간격36px.
- 767px 이하 두 이미지/글 구간과 세 기준1열. 640px 실화면에서 제목이 세 줄로 좁아져 전환 기준을 보정했다. DOM 순서를 유지한다.
- 내부 간격은 설명까지100px·세 기준까지90px·마무리88px. 작은 구성은56/52/52px. 고정 높이로 내용을 자르지 않는다.
- 브랜드 메뉴는 #brand로 이동하고 기존 #/brand는 이력을 더하지 않고 새 주소로 바꾼다. 기존 고정 헤더 스크롤 여백을 쓰고 제목에 포커스를 둔다. 모바일 메뉴의 닫기와 같은 위치 재선택도 유지한다.

히어로 높이·영상·상품·쇼핑 기능은 유지한다. CSS/라우트 연결에는 v7 계열 값을 붙여 이전 캐시를 피한다. 실제 확인과 한계는 [홈 브랜드 통합 검수](SHINE_SKIN_BRAND_HOME_QA.md)에 둔다.

## 18. 마우스에 반응하는 히어로 물결

2026-10-18 사용자 요청으로 첫 화면의 마우스 이동 위치에서 원형 물결이 퍼지는 효과를 추가했다. 꽃잎 배경이 물결 방향으로 약하게 굴절되고 가장자리에 밝음과 그림자가 생긴다. 기존 제목 유리·제품 영상·버튼보다 아래에 배치해 글자와 제품의 형태를 유지한다. 페이지 구조와 이동 흐름은 바뀌지 않는다.

- 시작: 정밀 마우스·호버가 가능한 환경의 히어로 pointermove. 처음 움직일 때만 기존 아이리스 배경을 캐시에서 불러와 WebGL을 준비한다. 새 이미지·라이브러리·외부 서비스가 없다.
- 움직임: 물결당 1,700ms, 반경 초당 185px로 확장, 900ms부터 잦아든다. 입력 간격 최소65ms·이동 거리24px, 동시 최대6개. 굴절 변위는 강도에 비례해 최대 약8px다. 색상은 배경의 푸른 계열을 따르고 추가 UI 문구는 없다.
- 성능: 화면용 버퍼 최대100만 픽셀·너비1440px·배율1, 그리기 빈도 상한30회/초. 진행 중인 물결 주위만 그리고 남은 물결이 사라지면 다음 프레임을 예약하지 않는다. 포인터/프레임 처리 중 레이아웃을 읽지 않는다. 이는 구현 상한이며 실기기 프레임 성능 보장은 아니다.
- 제어: 기존 shine-motionchange 이벤트를 공유한다. 히어로가 화면에서 사라지거나 탭이 숨겨지거나 푸터의 ‘움직임 줄이기’가 켜지면 즉시 지운다. 설정을 끄더라도 새 입력 전까지 물결은 생기지 않는다.
- 접근성: canvas는 aria-hidden·pointer-events:none이다. 키보드 이동·링크·메뉴를 가로채지 않는다. 터치·호버 없는 환경·데이터 절약·기기의 모션 축소 설정에서는 시작하지 않는다. WebGL 실패 시 배경과 콘텐츠를 유지한다.
- 반응형: 창 크기가 바뀌면 히어로 크기를 다시 측정하고 기존 물결을 지운다. 내부 overflow는 clip으로 처리해 작은 화면에서 포커스나 창 크기 변경 때문에 배경 레이어와 제목이 내부 스크롤로 어긋나는 현상을 방지한다. 기존 전체 화면 최소 높이를 유지한다.

수정은 index.html·glass-v2.css·새 hero-ripples.js에 한정한다. CSS는 v8.1, 새 스크립트는 v8로 연결해 이전 캐시를 피한다. 실제 확인과 미확인 환경은 [히어로 물결 검수](SHINE_SKIN_HERO_RIPPLE_QA.md)를 따른다. DESIGN.md·공통 토큰·와이어프레임의 구조는 보존한다.
